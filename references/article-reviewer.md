# Article Reviewer 联动流程

这份流程只在用户要求把本 Skill 的文章放进 Article Reviewer 打开、批注、继续修改或复核时使用。

## 打开文章

1. 先按本 Skill 的当前任务规则完成文章，或取得用户指定的当前正文。
2. Article Reviewer 是文章审阅页面与对话之间的唯一桥梁。工具可用时直接调用，不另做替代审阅页面；工具不可用时如实说明，不能假装已经打开。
3. 把完整正文转换为安全 HTML，保留标题层级、段落、图片位置、图注、来源和链接。
4. 同一篇文章使用稳定的 `documentId`。已经打开过的文章只按同一 ID 恢复最新版，不能用旧稿或聊天里的副本覆盖已保存版本。
5. 有源文件时先计算 SHA-256，并把 `sourcePath` 与 `sourceHash` 一起交给 `open_article_review`。没有源文件时直接打开当前成稿。
6. 调用 `open_article_review` 后停下来，让用户直接编辑或添加批注。

## 用户说“开始修改”

“开始修改”“按批注修改”或同义表达代表用户授权执行最新一轮改稿。收到后必须在同一轮完成下面的工作，不能只回复已经开始。

1. 确认当前对话最近打开的 `documentId`。没有明确文档或存在多个可能文档时，先请用户指出文章。
2. 第一项工具操作必须是用 `get_article_review` 读取该文档的最新版本。
3. 只把返回的 `articleHtml` 和批注视为当前正文。页面里的直接编辑已经包含在 `articleHtml` 中，不能退回磁盘旧稿、聊天旧稿或助手记忆。
4. 逐条处理所有有效批注。本 Skill 的写法规则用于完成批注要求，但批注只授权改动其指向的内容，不能顺手重写其他段落。
5. 批注位置或含义无法唯一确定时停止并指出具体批注，不能猜测。工具报错、正文为空或哈希冲突时停止，不保存替代版本。

## 保存与复核

没有源文件时，用读取结果中的版本号和状态哈希调用 `save_article_review`，保存修改后的完整 HTML，清空已处理批注，并使用由文档 ID、版本号和状态哈希组成的稳定 mutation ID。保存成功后重新调用 `open_article_review` 打开同一文档。只有重新打开并确认新版本后，才能告诉用户修改完成。

有关联源文件时，写入前重新计算源文件 SHA-256，并与审阅记录的 `sourceHash` 比较。匹配后先创建可恢复备份，再按源文件原格式写入，不能用原始 HTML 覆盖 Markdown 或其他格式。验证文件非空、图片和链接仍在，再保存无批注的审阅版本并重新打开。哈希不匹配或缺失时停止，让用户处理冲突。
